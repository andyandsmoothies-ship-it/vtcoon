# Operate

On an Operate surface the visitor came to get a job done, so the page or view is first a working product of its category and the visual world serves it.

## Directions

Someone who uses tools like this one should know where everything is before they notice the world. The world lends four things and only these: type, palette, density, and one signature move. It never supplies the layout, the navigation model, or the controls. Colour is part of the world's contribution, and it does real jobs: a committed palette for the shell (a coloured rail or header, a tinted ground), state colours, data series, selection, and the signature move. A grey screen with one accent colour is the category default without the category's polish, not restraint.

Read every candidate through that limit. A world taken from a tool or instrument the audience operates (a terminal, a scope, a control panel, a cockpit) comes back as a costume of that tool on a working screen: take from it only what transfers as type, palette, density, and a signature move. Platform conventions and familiar affordances must remain intact.

Write the first viewport as the product's shell first: the navigation, the work areas and what each is for, the data the visitor reads first and its states, and then where the signature move lives. Expression may never obscure the task, state, or familiar affordance. Name the signature move concretely so the build can find it.

## Comps & Layouts

The screen renders in the direction's committed palette: its shell and navigation with a distinct area for each job and, where there is data, filters over what they scope and charts and tables with clear states. The world enters only through type, palette, density, and the one signature move; it never supplies the page's organisation, so a working screen never reads as a poster or any other decorative artifact.

Every control is a standard one the visitor already knows how to use: buttons, tabs, inputs, selects, filters, tables with sortable headers, and navigation that reads as navigation. Never a costume of the world's own interface. The finish bar is the best product in the category: an aligned grid, consistent spacing, a real type scale, and clear hierarchy.

Prompt and build with the screen's real content: the product name, realistic data with plausible values and units, real labels, and one state worth seeing (an alert, a degraded state, an empty filter result), never placeholder tiles.
