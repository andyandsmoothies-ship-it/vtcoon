### 2.4. Hóa Giải Xung Đột LOC & Thiết Lập 5 Giao Thức Phòng Ngừa Post-Mortem
- **Xung đột LOC đã hóa giải:** Global ghi nhận nguyên tắc ủy quyền: `Project-specific linter budgets take precedence; otherwise enforce defaults`, kèm ngoại lệ `Functions: Max 30 LOC (declarative UI/textures exempt per project rules)`. Dự án VTCOON tiếp tục bảo lưu nguyên vẹn 3 tầng của [`scripts/lint_slop.mjs`](file:///c:/Users/HP/Documents/GitHub/vtcoon/scripts/lint_slop.mjs) (`TIER 1 <= 400`, `TIER 2 <= 500`, `TIER 3 <= 800`).
- **5 Giao thức cơ học từ Root Cause Post-Mortem được tích hợp:**
  1. *Subtractive Refactoring / Delete-First Audit:* Plan bắt buộc có mục `[DELETE / CLEANUP]` chỉ định rõ state/listener cũ cần xóa bỏ khi thay thế cơ chế. Cấm để listener cũ chạy song song.
  2. *Import DAG Check:* Kiểm tra các câu lệnh import đầu tệp của module đích trước khi export, triệt tiêu nguy cơ Circular Dependency.
  3. *Call-Site Exhaustion:* Cấm ỷ lại vào default parameter. Bắt buộc `grep_search` kiểm kê 100% callers trên cả `src/` và `tests/`.
  4. *Pre-Coding Delta LOC Calculation:* Với tệp $\ge 300$ LOC, bắt buộc tính `[Current + Delta = Expected]`. Nếu `Expected > Ceiling`, Task 1 bắt buộc là trích xuất submodule.
  5. *Mock Async Browser Web APIs:* Trong môi trường Vitest/Node, các API bất đồng bộ (`img.onload`, `requestAnimationFrame`, `AudioContext`, `canvas.getContext`) bắt buộc phải có harness mock tường minh kích hoạt handler, chống Pass giả (False Green).
