# PILLAR IV: NETWORK & SPARSE STATE SYNCHRONIZATION

> **Scope**: `src/server/network/`, `src/client/network/`, `src/domain/action_intent_types.ts`, `src/server/security/envelope_validator.ts`

---

1. **5-Station Vertical Slice**: Every new data field or event MUST traverse all 5 physical stations: (1) Root Entity/FSM; (2) DTO interface & Mappers (`PlayerDelta`, `buildDeltaFromRoom`); (3) Broadcaster diff (`isPlayerEqual` sparse whitelist); (4) Client Parser (`OPTIONAL_KEYS`); (5) Client Store & UI.
2. **Array Tombstone Protocol**: Dynamic collections (`hand`, `modifiers`, `mortgagedProperties`) when cleared MUST serialize an empty array `[]` (never serialize `undefined` or omit). Delta comparison `isPlayerEqual` must compare individual array elements to prevent clients from retaining deleted items.
3. **Explicit Tombstone Protocol (`null` vs. `undefined`)**: Removed object entities (e.g. `auction`, `lastTradeOffer`) MUST be explicitly assigned `null` on the server so client parsers recognize teardown and dismiss corresponding modals.
4. **Authoritative Resync on Client Ephemeral Timers**: All client countdown timers must bind effects to server delta fields (e.g. `auction.timeRemaining`), eliminating clock drift caused by network jitter or tab throttling.
5. **Monotonic Countdown Guard & Single Source of Urgency [IMP-207]**: When the client receives `delta.timeRemaining`, `apply_delta.ts` must suppress 1s upward clock jumps (41s -> 42s caused by `Math.ceil` phase mismatch), accepting only decrements or valid resets (turn advance, phase transition, doubles roll). In UI, during urgent subphases (Auctions, Bot Negotiations, Compulsory Buyouts), TopBar must suppress `role="timer"` to grant urgency authority to the contextual widget.
6. **Turn Timer SSOT Deadline & TopBar Zero-Freeze Guard [IMP-215]**:
   - **Server SSOT**: When a Bot takes a turn (`current.isBot === true`), `TurnOrchestrator` must set authoritative deadlines (`this.deadlines.set(roomCode, Date.now() + phaseTimeoutMs)`). Any phase transition or bot step MUST invoke `this.orchestrate(roomCode)` BEFORE calling `this.broadcaster.broadcastRoomDelta(roomCode)` so deltas always carry `timeRemaining > 0` SSOT for the upcoming phase.
   - **Client Non-Zero Guard**: `apply_delta.ts` maintains 2 layers of protection: (a) On turn change, if `delta.timeRemaining <= 0` or falsy, fall back to 60s; (b) Mid-turn (no turn/phase transition), NEVER overwrite to `0` (`delta.timeRemaining > 0 && delta.timeRemaining <= state.turnTimeRemaining`), preventing flashing `⏱️ 00:00` lockups on TopBar upon receiving mid-turn event deltas (paying rent, buying land).
   - **AFK Recovery Grace**: Preserve invariant `wasInAudit` (TC-151.04) in `executeSafeAfkAction`: when `player.wasInAudit === true`, clear flag `wasInAudit = false` and `return` to let `orchestrate` re-establish safety buffers.
7. **Wire Protocol Envelope Validator Intent Whitelist Parity [IMP-224]**:
   - **Purpose**: Ensure perimeter defense in `EnvelopeValidator` remains 100% synchronized with the catalog of Intents handled in FSM and `intent_dispatcher.ts`.
   - **Synchronized Whitelist**: When introducing any new Intent into FSM (`INTENT_AUTO_SOLVENCY`, `INTENT_ISSUE_BOND`, `INTENT_REPAY_BOND`), MUST declare simultaneously in `VALID_INTENTS` within `src/server/security/envelope_validator.ts`, preventing the WebSocket layer from rejecting packets with `INVALID_INTENT` prior to reaching domain handlers.
   - **Zero-Allocation $O(1)$ Schema Guards**: Use module-level static `Set` (`VALID_BOND_TRANCHES = new Set<string>(Object.values(BondTrancheId))`) to validate payload parameters (such as `trancheId` in `INTENT_ISSUE_BOND`). Optional parameters when absent (`undefined`) pass to FSM default fallbacks; when present, they must match valid enum whitelists.
8. **Subtractive Separation of Multi-Transaction Delta & Two-Phase Animation Pacing [IMP-230]**:
   - **Anti-Net-Delta Labeling**: When a player crosses GO and incurs a rent penalty within the same dice roll, network deltas carry only net balance (`diff = +2,000 - 1,980 = +20`). `apply_delta_players.ts` (and all low-level sync handlers) MUST NOT tag `isSalary` based on `isPassingGo` or `diff > 0`. Financial changes must be decomposed by `ActivityRentMatcher` and orchestrated by `ActivityBadgeDispatcher`.
   - **Two-Phase Animation Query (Pending & Active)**: When computing pass-GO badge delays (`getPawnPassGoDelay`), inspect both phases: (1) `state.pendingPawnMove` before animation start and (2) `state.activePawnAnimation` during board traversal. Use SSOT `checkPassedGo(fromCell, targetCell)` from `domain/room.ts` to calculate exact remaining steps to GO, eliminating timing conflicts with destination penalty badges.
9. **Sequential Modal Handover & Server-Authoritative Expiry [IMP-229]**:
   - **Network-Level Modal Hijacking Ban**: When server deltas deliver both `lastEventCard` and dependent interactions (`pendingBuyout`), `apply_delta.ts` MUST NOT open dependent modals while pawn movements are active (`isMoving = Boolean(activePawnAnimation?.isAnimating || isRolling)`) or during active event card flows (`isCardFlow`). Store data in Zustand store SSOT (`setPendingBuyout`) and hand off sequential modal transitions to `ModalHost` upon player confirmation of `EventCardModal`.
   - **Clock Skew Immunity & Server-Authoritative Watchdog**: Client timers compute relative 15s countdowns with fallback `safeInitialMs = Math.max(0, expiresAt - Date.now()) || 15_000`, decrementing 100ms/tick independently of `Date.now()`. When reaching 0s, the client MUST NOT trigger `onDecline()`; lock the Buy button (`disabled = true`, label 'Buy Window Expired') and defer timeout authority to Server Watchdogs (`delta.pendingBuyout = null`).
10. **Dynamic GO Salary & Event Penalty Separation Parity [IMP-234]**:
    - **Delta Pipeline Parity**: `RollResult` and `DeltaPayload` carry `passedGoSalary: number`. Clients prioritize `delta.passedGoSalary ?? calculateGoSalary(round)`, eliminating desync between credited domain balances and narrative text across Floating Badges and WSS notifications.
    - **Exact Match Event Penalty Distinction**: Identifying event penalties (`isCardPenalty`) requires 2 conditions: `(card.drawnBy === payer.id || card.playerId === payer.id)` and `Math.abs(card.effectDelta ?? 0) === absDiff`, eliminating false positives misattributing rent or land taxes as event penalties.
    - **Mobile Multi-Badge Pacing Ergonomics**: On mobile, when `latestMilestone` is present, hide older badges and display only the newest badge alongside MilestoneBanner ($\le 2$ items total, $\le 120$px). In the absence of milestones, display both Salary and Penalty/Rent badges concurrently.
